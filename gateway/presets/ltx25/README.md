# LTX-2.5 presets (Arc build)

Generated by `tools/convert_ltx_presets.py` from Lightricks/ComfyUI-LTXVideo `example_workflows/2.5` at commit `3bf3ca62595f1764c47d01c35c8e5dfe47e1a88f`. UI-format workflows: load in ComfyUI (or CueForge) directly. Regenerate: `python tools/convert_ltx_presets.py --src <clone>`.

## What changed vs the official graphs

- Transformer loader (`UNETLoader`, `ltx-2.5-22b-distilled-transformer-bf16`) -> `UnetLoaderGGUF` (ComfyUI-GGUF) loading `LTX-2.5-Distilled-Q4_K_M.gguf`. Both output MODEL on slot 0; no links changed.
- Gemma 12B encoder `CLIPLoader` -> `gemma4-12b-with-proj-ltx-2.5-comfy-int8-convrot.safetensors` (type ltxv kept).
- Video/audio VAE and x2 spatial upscaler names already match ours; unchanged.
- Everything else (sigmas, steps, sizes, tile sizes, switches) is the official calibrated default. Upstream `properties.models` download hints for the replaced files were removed.

## Runnable now (no IC-LoRA)

- `LTX-2.5_I2V_HDR_Two_Stage_Distilled`: HDR still → HDR video: EXR still → float32 VAE → EXR + HLG out.
- `LTX-2.5_A2V_Two_Stage_Distilled`: Audio-to-video. Encodes an input clip (with start + duration trim), freezes those tokens in both stages, and muxes the original waveform into the output (no audio decode). Optional first-frame image.
- `LTX-2.5_T2A_Single_Stage_Distilled`: Text-to-audio only. No video VAE or upscaler.
- `LTX-2.5_T2V_I2V_Single_Stage_Distilled`: Same text / image inputs, one distilled pass, no upscaler. Faster and lighter; lower spatial detail than two-stage.
- `LTX-2.5_T2V_I2V_Two_Stage_Distilled`: Start here. Text-to-video, optional first-frame image. Stage 1 at base resolution, 2× spatial upscale, then a 3-step refine. Generates video and audio together.

Caveats: the official graphs also load `gemma4_e2b_it_bf16.safetensors` (prompt-enhancer encoder, `TextGenerateLTX2Prompt`); it is NOT in our confirmed file list, so download it or the CLIPLoader fails validation (enhancer is on by default). `GemmaAPITextEncode` nodes are the cloud LTX API path, inert unless the ckpt name contains `ltxv_`. HDR I2V needs EXR input and the float32 VAE path; untested on XPU.
